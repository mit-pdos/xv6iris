#   tools/gen_ucode.py --module Sh --prog shk --out iris/UCodeShK.v \
#       --spec tools/ucode_shk.txt
#
# THE SECOND CATALOG OVER THE SAME DUMP.  tools/ucode_sh.txt drives
# iris/UCodeSh.v, which emits [uinstr] facts -- the PAGE-TABLE-indexed form
# the first-generation sh proofs (UProofSh*.v, on WpUmode*) take.  This file
# drives the catalog for the SAME image on the urun engine, whose leaves take
# [UserHeap.uinstr_is] -- a separation-logic resource that mentions no page
# table at all.  Both are on-build, so the two must not collide: [--prog shk]
# names what this file DEFINES ([shk_text_sub], [uis_shk_*], [shk_code]) while
# the dump maps it READS stay [ShInstrs.sh_bytes] / [ShData.sh_data].
#
# GROWS PER STAGE.  The SH lane of claude-notes/projects/fs-syscall-specs.md
# walks sh one stage at a time; each stage appends its functions here and
# regenerates.  An [ui_shk_*] fact for an instruction no proof fetches is not
# wrong, only compile time -- but a whole uncalled function would be a claim
# about code nothing reads, so it is left out and the reason recorded.
