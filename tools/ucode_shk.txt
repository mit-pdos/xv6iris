# ucode_shk.txt -- the pc set of iris/UCodeShK.v, for tools/gen_ucode.py.
#
# tools/ucode_manifest.json binds this spec to iris/UCodeShK.v; `make gen-ucode`
# rewrites that file from it, and `make check-ucode` fails if it moved.
#
# ONE OF THREE CATALOGS OVER THE SAME DUMP.  sh is split by STAGE, for the
# measured reason tools/ucode_shp.txt records: this file (SH lane stages 1-2
# and 5, plus the diagnostic subtree), tools/ucode_shm.txt (stage 3, the
# allocator) and tools/ucode_shp.txt (stage 4, the parser).  All three are
# on-build, so they must not collide: [--prog shk] names what this file
# DEFINES ([shk_text_sub], [uis_shk_*], [shk_code]) while the dump maps it
# READS stay [ShInstrs.sh_bytes] / [ShData.sh_data].
#
# GROWS PER STAGE.  The SH lane of claude-notes/projects/fs-syscall-specs.md
# walks sh one stage at a time; each stage appends its functions here and
# regenerates.  An [ui_shk_*] fact for an instruction no proof fetches is not
# wrong, only compile time -- but a whole uncalled function would be a claim
# about code nothing reads, so it is left out and the reason recorded.

note SH LANE STAGES 1-2, 5 and the DIAGNOSTIC SUBTREE.
note
note THE DIAGNOSTIC SUBTREE (ask 7) adds [panic], [fprintf], [vprintf] and
note [putc] -- the cone every one of sh's three fprintf-and-die tails runs
note through.  It is no longer cut: iris/UkShDiag.v walks it and discharges
note UkShRun.v's [ush_diag_leaf].  [printf] stays out because sh never calls
note it (every diagnostic in sh.c is an [fprintf(2, ...)]), and [printint]
note stays out because the only formats sh prints are "%s\n",
note "exec %s failed\n" and "open %s failed\n" -- vprintf reaches printint
note only from its %d/%u/%x arms, which those three format strings refute.
note
note STAGE 5 adds [runcmd] and [fork1] -- the command TREE walk -- with the
note six further usys.S stubs they and the [cd] builtin issue: fork, exec,
note pipe, wait, chdir and dup.  [runcmd]'s whole range is catalogued, the
note two fprintf-and-die tails included.
note
note SH LANE STAGES 1-2: the ELF entry, main's console preamble, and the
note COMMAND LOOP down to the blank-line test.  [start] calls [main]; main's
note first act is the loop that opens "console" until it owns fd 3, then it
note closes it and falls into the command loop, whose head reads a line with
note [getcmd] -- write(2,"$ ",2), memset(buf,0,100), gets(buf,100) -- and
note skips leading blanks.  open, close, exit and write take the QUIET row of
note the syscall memory table (UsysMemOk.usys_mem_ok); [read], which [gets]
note issues one byte at a time, takes the WINDOW row.
note
note The whole of [main] is catalogued, not just what is walked: the pc set is
note per function, and main's remaining arms -- the [cd] builtin at 0x96a and
note the fork/parse/run body at 0x908 -- are later stages over the same facts.

omit 0xc68 exit's [c.jr ra] -- the ecall at 0xc64 never returns

# THE IN-PAGE CLAUSE.  [UserHeap.uinstr_is] carries a temporary in-page
# clause: the fetch window stays on one page, i.e. [Z.rem (uint pc) 4096]
# is at most 4092, or 4094 for a compressed instruction (whose window at a
# 2-mod-4 pc is two bytes).  Before the a083670 bump the bound was a uniform
# 4092 and vprintf's [c.mv a1,a5] at 0xffe (the SECOND [putc] of the
# unknown-'%' arm, unreachable from sh's '%s' formats) was omitted; the
# 8-byte [seccomp] stub moved it past the boundary.  The d66e41c bump
# (sh's [cmdalloc], text -0x24) put vprintf's epilogue [c.ldsp s7,24(sp)]
# -- REACHED by every diagnostic -- at 0xffe, and the clause was relaxed
# to the compressed window rather than omit a fetched pc.  No listed pc
# violates it.

skipfunc printf unreachable: every diagnostic in sh.c is an [fprintf(2, ...)]
skipfunc printint unreachable: vprintf reaches it only from the %d/%u/%x
skipfunc printint arms, and sh's only conversion is %s

skipdefault not on stage 1's, 2's or 5's path: the [cd] builtin's body, the
skipdefault parser and the allocator are later stages of the SH lane, and this
skipdefault catalog grows to meet them
