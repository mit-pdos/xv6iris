# The Sail modules model/Lean_RV64D is generated from (sail-riscv 0.16 + the xv6 fork commits).
#
# This is xv6iris's own selection -- a curated subset of riscv.sail_project's
# modules, NOT `--all-modules` (upstream 0.16's default).  It is the pre-0.16
# selection plus Sdtrig; what it leaves out, and the fork commit that keeps the
# F/D instructions out despite 0.16's `postlude` dependency, are in
# notes/model-diffs.md.  It is recorded here because it is a build input for the
# generated model: change it and the model gains or loses whole instruction
# families.  tools/regen_sail_model.sh
# reads this file (comments and blank lines ignored; whitespace-separated
# module names), so a regen no longer depends on a cmake cache sitting in
# somebody's sail-riscv build directory.
#
# Note what is here and what these flags are NOT: Zba/Zbb/Zbc/Zbs/B_types and
# V_core/V_types ARE compiled into the model, and are then disabled by
# `sail-config-rv64d.json` (see its header).  Whether an extension is compiled
# and whether `hartSupports` answers true for it are independent axes.
# Conversely, F and D (and, per the configuration, Zfh and scalar crypto) are
# advertised but NOT compiled: `misa`/`hartSupports` report them, yet their
# opcodes decode as illegal (notes/model-diffs.md section 4).
