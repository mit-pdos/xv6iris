# Design: whole-system adequacy (RiscvAdequacy.v)

## Whole-system adequacy (RiscvAdequacy.v)

- `riscv_system_adequacy` is the Iris-adequacy instantiation (`wp_strong_adequacy`) for the multi-hart + device system; the file is a build LEAF (imports WpUart for `dev_inv_body`/`wp_dev_loop` and WireInv for `wire_inv`). Statement: pick a hart list `cs` and initial `gstate g` (hypothesis `Hram`: every byte of `g.(gmem)` is RAM); if for EVERY `riscvGS Σ` the initial resources — per-hart `reg_pointsto_at c r` over a caller-chosen register set `D c` (holding their `register_lookup` values at `g`), one `a ↦ₘ b` per initial memory byte, and `uart_frag`/`plic_frag` — entail, under a `={⊤}=∗` (allocate all invariants there: `dev_inv_body`, `wire_inv`, locks, `minstret_inv`, …), the WPs `WP (LoopE c) {{ _, True }}` for each `c ∈ cs` plus `WP DevLoop {{ _, True }}`, then every configuration reachable from the pool `cpu_pool cs = (LoopE <$> cs) ++ [DevLoop]` is reducible — a META-level safety statement with no Iris judgment in it (`to_val ≡ None`, so not-stuck = reducible and postconditions are vacuous). `riscvGpreS`/`riscvΣ`/`subG_riscvGpreS` are the standard pre-G plumbing. `riscv_device_adequacy` is the smallest end-to-end instantiation (`cs = []`, `D _ = {[sig_seip; sig_meip]}`, allocates `dev_inv_body` + `wire_inv`, concludes with `wp_dev_loop`) — use it as the template for hart clients. Registers outside `D c` are never allocated as ghost elems (no one can ever own them); a real instantiation puts every hart's `sig_seip`/`sig_meip` in `D c` (the wire invariant `wire_inv`, WireInv.v, owns the pins) plus each hart's boot-config registers. Both theorems are axiom-clean (baseline 5).
- Proof-technique gotchas baked into that file: (a) the caller's WPs live under the fixed instance `riscv_irisGS`, and `wp` is SEALED, so `wp_strong_adequacy`'s `IrisG …` record must be CONVERTIBLE to `riscv_irisGS` — instantiate the `state_interp_mono` existential with the PROJECTION `@state_interp_mono HasLc riscv_lang Σ (@riscv_irisGS Σ HR)` (a fresh proof term breaks convertibility since the Qed-opaque obligation can't be re-proved convertibly); build `HR := RiscvGS Σ Hinv _ f Hgen _ _ γu γp` with `set` so projections ι-reduce. (b) `rewrite big_sepS_list_to_set` silently NO-OPS inside a proofmode goal (consumes its side-condition branch but rewrites nothing) — bridge `[∗ list] c ∈ enum CPU` ↔ `[∗ set] c ∈ fin_to_set CPU` via the standalone entailment `big_sepL_enum_to_set` and `iApply` it. (c) A `CPU → gname` family is allocated by list recursion patching `fun c' => if decide (c' = c) then γ else f c'` (`reg_alloc_cpus`; needs `NoDup`); the caller-facing register elems come from `ghost_map_alloc` of `reg_init_map rs D` (`set_to_map`; `lookup_set_to_map` + `big_sepM_dom` convert map-elems to `[∗ set]`). (d) `sig_seip` alone is `register_bitvector_1`; in a `gset register` literal write `{[ (sig_seip : register) ]}` to trigger the `R_bitvector_1` coercion.


## The trace invariant: exporting a pure fact from an Iris invariant (`Hphi`)

- **What the top-level theorems now say.** `riscv_power_adequacy`, `xv6_power_adequacy`, `xv6_fs_adequacy` and every corollary below them conclude a CONJUNCTION: `(forall e2, e2 ∈ t2 -> reducible e2 g2) /\ phi g2`, for a client-chosen `phi : gstate -> Prop`. Because `t2`/`g2` are universally quantified over `rtc erased_step` from the initial configuration, proving `phi` at an ARBITRARY reachable state IS "`phi` holds at every state of the CSL-free execution" — the quantifier is the trace statement, no per-step machinery is involved. This is what `iris.program_logic.adequacy`'s `wp_invariance` packages; we cannot use that corollary (it fixes one initial thread and `num_laters_per_step := 0`), so the same conclusion is taken out of `wp_strong_adequacy` directly.
- **The one shape a `phi` can be proved in** is `state_interp g' ∗ ▷ I ⊢ ◇ ⌜phi g'⌝`, and both halves are forced. `state_interp` is the ONLY tie between the logic and `gstate` — an `iProp` invariant does not mention the machine at all, so every pure consequence is an auth/fragment agreement against one of `power_interp`'s conjuncts. And `I` must be an invariant this proof can NAME: the crash predicate `Pc` is the only one (it is allocated once into the fixed layer, so it is the same invariant at every point of the trace and across every power cycle), which costs nothing because `Pc` is an arbitrary `iProp` — a client wanting more invariants conjoins them into its own `Pc`. The hook is `Hphi`, stated at the RAW gnames as the `boot_fixedGS` literal, exactly like `HPc`/`Hproj`/`Hswap` and for the same reason (the client writes `Pc` in a context with no `riscvFixedGS`).
- **Why it lands in `⌜_⌝` and not some other `iProp`.** `wp_strong_adequacy`'s final continuation runs at `|={⊤,∅}=>`, so every invariant may be opened and NEVER closed — world satisfaction is spent. The soundness lemma underneath (`step_fupdN_soundness_gen`, then `pure_soundness`) demands a `Plain` conclusion. "The invariant still holds" is not statable; a `Prop` about `g2` is. The `◇` in `Hphi` is what strips `Pc`'s `▷` (an arbitrary `Pc` is not timeless); it is absorbed by the ambient fancy update.
- **`Hphi` IS NOT A DISK CHANNEL** — it takes the whole `power_interp g'`. The helpers in `RiscvAdequacy.v` are ADAPTERS, one per conjunct, not the interface: `power_interp_disk_auth` (the durable disk's auth — a FIXED conjunct, hence available with the power OFF too); `power_interp_era` (the gateway to every PER-ERA conjunct — `gregs_interp_at` for registers, `gen_heap_interp` for all of memory, `dev_interp_at` for the device fabric's three half-`ghost_var`s at `duart`/`dplic`/`dvirtio`; needs `gpow g = true` and the client's own `era_registered` receipt); `power_interp_resv_ok` (the degenerate case: a conjunct that is ALREADY pure, so no invariant is involved). A UART or memory trace invariant is the same two-line agreement the disk one is, guarded by `gpow` because between a PowerOff and the next PowerOn there is no era and hence no ghost state describing registers, memory or devices. Only the fixed conjuncts support an UNGUARDED trace invariant.
- **`disk_proj_trace` makes the disk case free.** `Hproj` (the per-boot pure projection, stage H0) already has the shape `disk auth ∗ ▷ Pc -∗ ◇ (… ∗ ⌜Ppure dk⌝)`; `disk_proj_trace` promotes exactly that to `Hphi`'s shape by pulling the auth out of `state_interp`. The two hooks read the same fact off the same invariant — the difference is only WHERE it is delivered (into each boot, versus out of the whole execution). `SystemAdequacy.fs_trace_hook` is that composition at `FsCrash.P_fs_named`/`P_fs_project`, so the FS's durability record costs no new proof.
- **The worked instantiation** is `SystemAdequacy.xv6_trace_pure` / `xv6_trace_hook` / `xv6_trace_invariant`, and it is deliberately TWO conjuncts through two different conjuncts of `state_interp`: `fs_boot_pure` (the disk, via the crash invariant) and `gpow g = true -> resv_ok g` (the era, via no invariant at all). `FsAdequacyImg`'s two image corollaries conclude it at the literal mkfs image. Order matters inside `xv6_trace_hook`: run the PURE-concluding projection first (a pure conclusion is persistent, so `iDestruct … as %H` does not spend `state_interp`), then the `◇`-concluding one, which does.
- **What is still on the table, and why it is not taken.** (a) `phi` could also range over the thread pool `t2` — `wp_strong_adequacy` supplies `t2 = es' ++ t2'`, `length es' = length es`, and passes `nt = length t2'` to `state_interp` — but `riscv_irisGS`'s `state_interp` is `fun g _ _ _ => power_interp g` and ignores both the step count and the thread count, so nothing about `t2` is tied to the logic; exploiting it means threading `nt` into `power_interp` and every fork rule. (b) `state_interp` also receives the observation list, and adequacy quantifies over the whole `κs`, so a `phi` over the entire OBSERVABLE trace (e.g. the exact sequence of UART bytes) is available in principle — but `RiscvLang.mobs := Empty_set`, the language emits nothing, so that channel is empty until an observation is added. (c) The `Φs`/`fork_post` clauses are dead: `mval := Empty_set`, so `to_val` is always `None`. (d) Iris adequacy is POINTWISE IN THE STATE — it gives `phi` at each reachable state, never a relation BETWEEN states ("the committed FS view only grows", "the log is never rewound"). The plain-Iris way to get those is a ghost HISTORY: either inside `Pc` (cheap — `Pc` is fixed-layer and can maintain a monotone list itself, no step rule changes) or inside `state_interp` (strictly more general, but every step rule must extend it). Neither needs new metatheory. Liveness, refinement and hyperproperties do, and are out of `wp_strong_adequacy`'s reach entirely (Trillium-style trace-indexed `state_interp`).
